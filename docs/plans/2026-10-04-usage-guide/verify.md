## 남은 리스크

- **테스트 러너 없음 (리스크 중)** — 이번 기능은 화면·문서 위주라 위 시나리오 확인으로 대체했다. 도입한다면 순수 함수가 모인 `src/lib/`(`attendance-range.ts`·`birthdays.ts`·`lunar.ts`·`phone.ts`)가 첫 후보
- 캡처는 앱 화면이 바뀌면 낡는다 → `guide/README.md` 절차로 다시 찍는다
- 실시트 환경의 화면 동작(실데이터 양·실제 비밀번호)은 이 검증 범위 밖 — 배포 후 실제 기기에서 메인 → 사용 안내 진입을 한 번 확인 권장

## 사용자 확인 후 수정 (2026-10-05)

학생 관리 화면은 **총무팀 선생님만** 쓰므로 안내 대상을 실제 운영에 맞췄다(문구만, 캡처·구조 변경 없음).

- 2절 3단계 힌트: "학생 관리의 '지난 출석 고치기'를 보세요" → "지난 출석을 고치려면 총무팀 선생님에게 문의하세요."
- 5절 들어가기 2단계: "모르면 담당 교역자께 물어보세요." 삭제
- 5절 지우기 경고: "담당 교역자께" → "담당 선생님이나 총무팀 선생님에게"
- 자주 묻는 것 "카드를 눌러도 아무 반응이 없어요": 지난 출석 안내를 총무팀 선생님 문의로 (같은 성격의 "비밀번호" FAQ는 사용자 결정으로 유지)
- 재확인: `npx tsc --noEmit` exit 0, `npm run build` exit 0
