# 출석부 사용 안내 페이지

- 작성일: 2026-10-04
- 상태: 승인됨 (2026-10-04 사용자 승인, 같은 날 범위 수정 — 생일자·교사 현황 포함, 사용자 시나리오 추가)

## 배경 / 문제
출석 카드는 주일에 **학생이 직접** 누르고, 교사는 반별로 잘 눌렸는지 확인·정정한다. 처음 온 학생·새 교사가 쓸 사용법 안내가 앱 안에 없다.
참고 디자인: claude.ai 아티팩트 "학생 정보 수정·삭제 안내" (휴대폰 캡처 + 빨간 네모 + 단계 번호, 앱 토큰 동일)

## 목표
- 앱 안 `/guide` 페이지 하나로 출석 체크·확인, 출석현황, 생일자, 학생 관리(등록 포함)·교사 현황 사용법을 안내한다
- 메인 화면에서 PC·모바일 모두 한 번에 들어갈 수 있다

## 비목표 (이번에 하지 않는 것)
- 교적부(`/registry`) 가이드
- PC 화면 캡처 (본문에 "PC에서는 헤더 버튼" 정도의 글 안내만)
- 화면별 도움말(?) 버튼, 동영상, 가이드 내용 편집 기능, 다크 모드(앱에 실제 적용되어 있지 않음)

## 사용자 시나리오
VERIFY 단계는 이 시나리오를 따라가며 동작을 확인한다.

1. **처음 온 학생** — 주일에 교회 기기로 출석부를 연다 → 모바일 메뉴(☰)에서 `사용 안내`를 누른다 → "출석 체크하기"를 보고 세션을 확인한 뒤 자기 이름 카드를 눌러 도장이 찍히는 것을 확인한다.
2. **반 담당 교사** — 예배 중 휴대폰으로 `사용 안내` → "출석 확인하기"를 본다 → 메인에서 반 필터로 자기 반만 보고, 출석 안 된 카드 중 실제로 온 학생을 대신 누른다. 지난주 기록이 빠진 걸 발견하면 안내대로 학생 관리에서 고친다.
3. **출석 통계를 보는 교사** — `사용 안내` → "출석현황 보기"를 보고 출석현황 화면에서 기간을 4주로 바꿔 반별 평균과 결석 배지를 눌러 명단을 확인한다.
4. **생일 축하를 준비하는 교사** — `사용 안내` → "생일자 보기"를 보고 생일자 화면에서 다음 달로 넘겨 명단을 확인한다(음력 표시 포함).
5. **새친구를 맞은 관리자** — `사용 안내` → "등록하기"를 보고 학생 관리 화면에서 `새친구 등록`으로 등록한다 → 메인 출석부에 카드가 생긴 것을 확인한다. 몇 주 뒤 반을 배정받으면 "정보 고치기"대로 학년·반을 바꾼다.
6. **교사 연락처를 찾는 관리자** — `사용 안내` → "교사 현황 보기"를 보고 학생 관리 → `교사 현황`에서 팀 탭·이름 검색으로 찾아 연락처를 눌러 전화한다.
7. **비밀번호 없이 링크로 들어온 사람** — `/guide` 주소로 바로 들어오면 교사용 비밀번호 창이 먼저 뜬다.

## 설계 요약
**진입 버튼** (메인 `/`에만)
- PC: 헤더 버튼 줄 맨 끝(`학생 관리` 오른쪽)에 테두리형 `? 사용 안내` — `/members`의 `교사 현황` 링크(테두리형)와 같은 스타일
- 모바일: `MobileNavMenu` items 맨 아래 항목 추가

**`/guide` 페이지** (교사용 `PublicGate` 뒤, 한 페이지 + 상단 바로가기)
1. 출석 체크하기 (학생용) — 세션 확인 → 내 이름 카드 누르기 → 도장 → 잘못 누르면 한 번 더 눌러 취소
2. 출석 확인하기 (교사용) — 반 필터 → 요약 숫자·미출석 카드 확인 → 빠진 학생 대신 누르기. 카드는 **오늘만** 눌림(지난 주는 5-4), 다른 기기 반영은 최대 30초
3. 출석현황 보기 — 날짜·기간 → 반별 차트 → 행 눌러 명단 → 기간 모드 개근·부분·결석 배지
4. 생일자 보기 — 메인의 `생일축하`로 진입 → 세션 확인 → 이전/다음 달 넘기기 → 학년·교사·새친구별 명단, `(음력)` 표시 의미
5. 학생 관리 (관리자 비밀번호)
   - 5-1 들어가기
   - 5-2 **등록하기** — 헤더의 `학생 등록`·`교사 등록`·`새친구 등록` 버튼(모바일은 `학생`·`교사`·`새친구`로 짧게 표시)
     - 학생: 필수 소속·이름·학년·반
     - 새친구: 학년이 `새친구`로 고정, 반 칸은 비활성
     - 교사: 필수 소속·이름·팀
     - 등록하면 출석부 메인에 바로 카드가 생김
   - 5-3 정보 고치기 (교사도 같은 방식) — 새친구가 반 배정을 받으면 학년·반을 바꿔 정식 편입
   - 5-4 지난 출석 고치기
   - 5-5 지우기 (경고 상자: 출석 기록도 함께 삭제, 되돌릴 수 없음)
   - 5-6 **교사 현황 보기** — 학생 관리 헤더의 `교사 현황`으로 진입(같은 관리자 인증이라 다시 묻지 않음) → 세션·팀 탭 → 이름 검색 → 컬럼 눌러 정렬 → 연락처를 누르면 전화 연결, 출석률(1년 기준) 읽는 법
6. 자주 묻는 것 (접기)

**디자인**: 앱 토큰(paper·ink·stamp·teal·gold) + `font-display` 그대로. 단계 = 번호 + 설명 + 완성 이미지(휴대폰 틀·빨간 네모가 합성된 것). 모바일 세로, `md` 이상 좌우.

**만드는 곳과 보여주는 곳 분리** (사용자 요청 2026-10-04)

```
guide/                 ← 가이드 작업 전용 (배포 안 됨, 저장소 루트)
├── README.md          실행 방법 안내 (화면이 바뀌면 다시 찍는 법)
├── mock/              가짜 시트 — /api/* 요청 가로채기 + 더미 데이터 JSON
├── capture/           화면 캡처 순서 스크립트 (.mjs)
├── pages/             이미지용 HTML — 캡처에 휴대폰 틀·빨간 네모를 합성
└── output/            완성된 안내 이미지
        │ 복사
        ▼
public/guide/          ← 보는 단계 (배포됨, 교사가 보는 이미지만)
└── *.png
```

**스프레드시트는 건드리지 않는다** (실시트·테스트 시트 모두)
- 6개 화면이 모두 클라이언트 컴포넌트라 데이터는 전부 브라우저 → `/api/*` 요청으로 온다(확인함). 이 요청을 브라우저에서 가로채 `mock/`의 더미 JSON으로 응답하면 Next 서버의 Route Handler까지 가지 않으므로 구글 시트 호출이 0회다
- `/api/auth`도 가로채서 비밀번호 없이 게이트를 통과한다
- `agent-browser network route <패턴> --body <json>`으로 가로챈다. 고정 응답이라 "출석 누르기 전/후", "등록 전/후"처럼 상태가 바뀌는 장면은 `capture/` 스크립트가 단계마다 응답을 바꿔 끼운다
- 이중 안전장치: ① 촬영 시 `**/api/**`는 기본 차단하고 필요한 경로만 mock(화이트리스트) ② 촬영용 dev 서버는 `GOOGLE_SPREADSHEET_ID` 등을 비운 채 실행 → 가로채기가 빠져도 실시트에 닿지 않음
- 앱 코드(`src/`)는 촬영을 위해 바꾸지 않는다

**기타**
- `/guide` 페이지(`src/app/guide/`)는 `public/guide/`만 참조한다. `guide/`는 앱 코드에서 참조하지 않는다
- 스크립트는 `.mjs` — `tsconfig.json` include가 `**/*.ts(x)`·`**/*.mts`라 `tsc`·`next build` 대상이 아님(확인함)
- `guide/`의 데이터·캡처는 모두 더미이므로 커밋 가능. 실데이터 화면은 어디에도 저장하지 않는다
- 촬영: 모바일 뷰포트(390×844, 2배)
- 빨간 네모는 `pages/`에서 이미지에 **합성**한다 → `/guide` 페이지는 완성 이미지 + 글만 보여 주면 된다(앱 쪽 오버레이 컴포넌트 불필요)
- 생일자 촬영용 더미 데이터에는 이번 달·다음 달 생일자와 음력 생일 교사를 넣는다. 교사 현황 촬영용 더미에는 여러 팀과 출석률 값을 넣는다(`/api/stats/rates`도 mock 대상)
