# 말씀노트 기록 관리 (sermon-notes)

- 작성일: 2026-11-01
- 상태: 승인됨 (2026-11-06)
- 구현 계획: ./plan.md

## 배경 / 문제
고등부는 학생들이 쓴 말씀노트(설교노트)를 반별 보관함에 모으고, 4개월마다 12회 이상 쓴 학생에게 상을 줄 계획이다.
지금은 누가 언제 썼는지 기록할 곳이 없어 총무팀이 시상 대상을 확인하려면 노트를 일일이 세어야 한다.
학생 명단·연락처는 이미 출석부 스프레드시트(Students)에 있으므로, 이를 그대로 활용해 기록과 집계를 앱 안에서 처리한다.

## 목표
- 교사가 반별 보관함의 QR을 찍어 **비밀번호 없이** 그 반 명단을 열고, 날짜별(과거 날짜 포함)로 말씀노트 작성 여부를 체크한다
- 작성 여부는 썼는지만 본다(내용 길이 무관)
- 총무팀이 **4개월 단위 기간별**로 작성 횟수순 명단(세션·학년·반·이름·전화번호·횟수)을 보고, 12회 이상 수상자를 바로 확인·복사한다
- 올해의 지난 기간 결과도 같은 화면에서 기간만 바꿔 본다

## 비목표 (이번에 하지 않는 것)
- **새친구**(학년 `새친구`, 반 없음) — 체크·종합 화면 모두 대상에서 제외. 반이 배정되면 그때부터 기록 (2026-11-01 사용자 결정)
- **교사**의 말씀노트 기록
- 노트 내용·분량 입력, 사진 첨부
- 반이 비어 있는 학생(데이터 누락)용 QR — 반이 채워지면 자동으로 해당 반 명단에 들어간다
- 수상 확정 스냅샷·수상 이력 저장 (기간을 다시 조회하면 되므로)
- QR 이미지 생성 기능 — URL 목록만 스크립트로 출력하고 QR은 무료 생성기로 만든다
- 데이터 API 전반의 서버 인증 도입 (CLAUDE.md "보호 수준은 화면 레벨" 범위 유지. 단 새 토큰 API는 서버에서 범위를 강제)
- `toStudent` 중복(라우트 3곳) 공용화 리팩터링
- **지난해 기간 조회** — 앱은 현재 시트만 읽는다. 3기 명단은 시트 전환 전에 복사해 둔다 `(대화에서 확정)`
- 기간 길이를 바꾸는 설정(4개월 고정), 12회 기준을 바꾸는 설정(상수)

## 사용자 시나리오
1. **반 교사 — 이번 주 체크:** 주일 예배 후 교사가 → 반 보관함 칸의 QR을 휴대폰으로 찍어 → 비밀번호 없이 `오전 · 1학년 2반` 명단이 열리고 날짜는 오늘(최근 일요일)로 잡혀 있음 → 노트를 낸 학생 카드를 누름 → 카드가 즉시 체크되고 상단 `12명 중 7명 체크`가 올라가며, 시트에 행이 생긴 것을 확인
2. **반 교사 — 지난 주 몰아서 체크:** 교사가 → QR 화면에서 → 날짜를 지난 일요일로 바꿔 체크 → 그날 기록으로 저장되고, 그날 결석한 학생 카드는 흐리게 `결석` 표시가 보임 (체크는 가능)
3. **반 교사 — 잘못 체크 취소:** 교사가 → 체크된 카드를 다시 누름 → 체크 해제되고 시트 행이 삭제됨
4. **두 교사 동시 체크:** 같은 반을 두 교사가 각자 휴대폰으로 체크 → 30초 안에 서로의 체크가 화면에 반영되고, 같은 학생은 그날 1회로만 집계됨 (거의 같은 순간의 저장은 행이 2개 생길 수 있으나 횟수에는 1회, 해제하면 모두 삭제)
5. **외부인 — 주소 조작 시도:** QR 주소의 토큰을 바꾸거나 다른 반 학생 ID로 저장 요청 → 404/403으로 거부되고 다른 반 명단은 보이지 않음
6. **총무팀 — 시상 명단 확인:** 총무팀이 → `/members`(admin 비밀번호)에서 `말씀노트` 버튼 → 종합 화면에 현재 기간(`2026년 3기 (9~12월)`)이 횟수순으로 나옴 → `시상 기준 12회` 구분선 위가 시상 대상이다. `시상 명단 복사` → 카톡/엑셀에 세션·학년·반·이름·전화번호·횟수가 붙여짐
7. **총무팀 — 지난 기간 조회:** 총무팀이 → 기간 드롭다운에서 `2026년 2기 (5~8월)` 선택 → 그 기간 집계가 나오고 분모는 그 기간 일요일 수(`12 / 18`)
8. **게이트 캐시 경로:** 다른 화면에서 데이터를 받은 뒤 `/notes/summary`로 이동 → 비밀번호 통과 전에는 명단이 전혀 보이지 않음
9. **관리자 — 학생 삭제:** 관리자가 → `/members`에서 학생 삭제 → 그 학생의 출석·말씀노트 기록이 함께 지워지고 다른 학생 기록은 그대로

## 설계 요약
**선택한 안**
- **저장:** 기존 출석부 스프레드시트에 `SermonNotes` 탭 추가 (`Date, Session, Grade, Class, StudentID, Name, Timestamp`). 행 있음 = 작성. Attendance와 같은 규칙·같은 멱등 저장 패턴. 시트에는 원자적 쓰기가 없어 동시 저장 시 중복 행이 생길 수 있으므로, **집계는 날짜 Set으로 1회만 세고 해제는 그 학생·그날 행을 모두 지운다**
- **체크 화면 인증 = 반별 비밀 토큰 링크** `/notes/c/[token]`. 토큰 = `HMAC-SHA256(NOTES_QR_SECRET, "세션-학년-반")` 앞 16자(base64url). 서버가 Students의 반 목록에 대해 HMAC을 계산해 일치하는 반을 찾음(토큰 저장 불필요, `timingSafeEqual` 비교). 유출 시 비밀값 교체 + QR 재인쇄
- **토큰 API가 범위를 강제:** 그 반 학생의 ID·이름(+그날 작성·출석 여부)만 반환, 저장 시 같은 반 소속과 **날짜(형식·일요일·미래 아님)를 서버에서 검증**. `/api/roster`(연락처 포함)는 쓰지 않음
- **종합 화면 = admin 게이트** `/notes/summary`, `/members` 헤더 버튼으로 진입. 카드 행 목록 + `시상 기준 12회` 구분선 + 기간·세션 탭·시상 명단 복사(시안 B2, 2026-11-06 사용자 결정 — `12회 이상만` 토글과 컬럼 정렬은 구분선으로 대체). 통과 전 렌더 차단. 집계 API `/api/notes/summary`는 기존 데이터 API와 같은 수준(서버 인증 없음, 화면 레벨 보호)
- **기간 = 1~4월 / 5~8월 / 9~12월 고정**, 분모는 그 기간 전체 일요일 수로 고정 — 진행 중이어도 같고 교적부 반기 컬럼과 같은 규칙 `(대화에서 확정)`. 드롭다운은 **올해 3개 기간만** 보여 준다 `(대화에서 확정)`. 시트가 연 단위라 지난해 기록은 읽을 수 없고, 그대로 두면 전원 0회로 잘못 표시된다
- **학생 삭제 시 SermonNotes cascade 삭제** (Attendance와 같은 이유: 같은 해 ID 재사용 오염 방지)
- **날짜:** 기본 최근 일요일(KST), 일요일만, 올해 안의 과거 가능·미래와 지난해 불가
- **UI는 아티팩트 시안 2~3안을 먼저 보고 확정**한 뒤 구현 (`design: existing` — 기존 색 토큰·티켓 카드 스타일 범위 안)
- **디렉토리:** 루트 별도 폴더가 아니라 `src/` 각 층에 `notes` 이름으로 (`app/notes`, `app/api/notes`, `components/notes`, `lib/notes-*.ts` …). Students는 앱 공유 데이터로 보고 말씀노트 API가 서버에서 직접 읽음. 의존은 말씀노트 → 시트(읽기) 한 방향

**검토했지만 버린 안**
- 별도 스프레드시트 — 환경변수·서비스 계정 공유가 늘고 이점 없음
- `?session=&grade=&class=` 평문 URL — public 저장소라 주소 규칙이 공개되어 다른 반 열람·조작 가능
- QR 화면에 기존 교사용 비밀번호 — QR 스캐너가 새 탭으로 열어 `sessionStorage`가 매번 비어 사실상 매주 입력
- 토큰 목록을 시트에 저장 — HMAC이면 관리할 데이터가 없음
- 12회 이상 전용 화면 별도 — 종합 화면의 구분선으로 충분
- `src/features/notes/` 기능별 폴더 — 이 프로젝트에서 혼자 규칙이 다른 섬이 됨

## 성공 기준
- [ ] QR 토큰 링크로 비밀번호 없이 그 반 명단이 열리고, 체크/해제가 즉시 반영되며 시트 행이 추가·삭제된다
- [ ] 잘못된 토큰은 404, 다른 반 학생 저장 요청은 403. 토큰 API 응답에 이름 외 개인정보(전화·주소 등)가 없다
- [ ] 같은 요청을 두 번 보내도 같은 날·같은 학생 행은 1개. 중복 행이 있어도 횟수는 1회이고, 해제하면 그 행이 모두 지워진다
- [ ] 기본 날짜가 최근 일요일이고, 일요일 외·미래 날짜는 선택할 수 없으며, 과거 일요일은 체크된다. API로 평일·미래·지난해·잘못된 형식의 날짜를 보내면 400으로 거부된다
- [ ] 그날 결석한 학생이 흐리게 `결석`으로 표시된다
- [ ] 종합 화면이 횟수 내림차순(동률은 학년→반→이름)으로 나오고, 12회 구분선이 맞는 위치에 있으며, 기간 전환·세션 탭·시상 명단 복사 결과가 시트와 일치한다
- [ ] 기간 경계(4/30·5/1·8/31·9/1·12/31)가 정확하고 분모가 그 기간 일요일 수다
- [ ] 기간 드롭다운에 올해 3개 기간만 나온다
- [ ] 새친구는 체크·종합 화면 어디에도 나오지 않는다
- [ ] 다른 화면을 거쳐 `/notes/summary`로 와도 admin 통과 전에는 데이터가 렌더되지 않는다
- [ ] 학생 삭제 시 출석·말씀노트 기록이 함께 지워진다
- [ ] 기존 7개 화면·기존 API 동작이 그대로다 (plan.md 6단계 회귀 점검 통과)
- [ ] `npx tsc --noEmit`, `npm run build` 통과
- [ ] 비밀값·실제 토큰·QR URL·실명이 저장소에 없다
