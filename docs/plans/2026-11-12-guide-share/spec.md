# 사용 안내 항목 공유 · 캡처 스켈레톤

- 작성일: 2026-11-12
- 상태: 승인됨
- 원래 기능: [2026-10-04-usage-guide](../2026-10-04-usage-guide/spec.md) (완료)

## 배경 / 문제
사용 안내(`/guide`)는 절·작은 주제가 접힌 채 시작하고, 주소 앵커(`/guide#members-delete`)로 들어오면 그 항목을 펼쳐 이동하는 기능이 이미 있다. 비밀번호 게이트를 통과한 뒤에 본문이 마운트되므로 앵커도 그대로 살아남는다.
그런데 이 앵커 주소를 꺼낼 방법이 없다. 칩·목차로 이동해도 주소창이 바뀌지 않고, 공유 버튼도 없다. 교사 단톡방에서 "학생 지우는 법은 여기 보세요"처럼 특정 항목을 바로 보내기 어렵다.
또 `/guide` 링크를 카톡에 보내면 루트 레이아웃의 공통 미리보기("서울광염교회 고등부 출석체크")가 떠서 사용 안내 링크인지 알아보기 어렵다.
마지막으로, 캡처는 절을 펼친 순간에 한꺼번에 받는데 받는 동안 그 자리가 빈 종이색으로 비어 있다. 공유 링크로 들어오면 펼쳐지자마자 빈칸이 여러 개 보여 깨진 화면처럼 느껴진다.

## 목표
- 각 절·작은 주제에서 그 항목으로 바로 열리는 링크를 한 번에 공유할 수 있다
- 칩·목차로 이동하면 주소창 `#`도 그 항목으로 바뀌어, 주소창을 복사해도 같은 위치가 공유된다
- `/guide` 링크를 카톡에 보내면 사용 안내 전용 제목·설명이 미리보기 카드에 뜬다
- 캡처를 받는 동안 그 자리에 휴대폰 모양 스켈레톤이 보이고, 다 받으면 캡처로 자연스럽게 바뀐다

## 비목표 (이번에 하지 않는 것)
- 카카오 API·SDK 사용 (앱 키·스크립트·환경변수 추가 없음)
- 항목마다 다른 미리보기 카드 — `#` 뒷부분은 서버로 전달되지 않아 불가능
- 단계(GuideStep) 단위 공유·앵커 — 단계가 42개라 버튼이 어수선해진다 (검토 후 제외)
- 사용 안내 전용 미리보기 이미지 생성 — 한글 글꼴을 넣어야 해서 작업이 커진다. 기존 `og-img.png` 재사용 (대화에서 확정)
- 공유 링크로 게이트 우회 — 받은 사람도 교사 비밀번호가 필요한 게 의도된 동작
- 뒤로가기로 이전 항목 돌아가기 — 주소 갱신은 `replaceState`라 기록을 쌓지 않는다
- 캡처 흐린 미리보기(`placeholder="blur"`) — 42장 각각 blurDataURL을 만들어야 한다 (검토 후 제외)
- 캡처 용량 줄이기·재촬영 — 스켈레톤은 캡처 파일을 건드리지 않는다

## 사용자 시나리오
1. **휴대폰 공유:** 총무팀 교사가 휴대폰 → `/guide` → 학생 관리 > 지우기 머리의 공유 버튼을 누름 → 공유 시트에서 카톡 선택 → 메시지에 세 줄 문구(제목·비밀번호 안내·링크)가 들어 있는지 확인
2. **받은 사람:** 교사가 카톡 링크를 누름 → 사용 안내 미리보기 카드 확인 → 비밀번호 입력 → 학생 관리 절과 지우기 주제가 펼쳐진 채 그 위치로 이동했는지 확인
3. **PC 복사:** 관리자가 PC 브라우저 → `/guide` → 출석현황 절의 공유 버튼 → "링크 복사됨"과 체크 아이콘이 2초 보였다 사라지는지, 붙여넣으면 세 줄 문구가 나오는지 확인
4. **주소창:** 교사가 `/guide` → 상단 칩(또는 왼쪽 목차·대상별 카드)으로 생일자 이동 → 주소창이 `/guide#birthday`로 바뀌었는지 확인
5. **공유 취소:** 휴대폰에서 공유 시트를 열었다가 닫음 → 오류 문구가 뜨지 않는지 확인
6. **캡처 로딩:** 교사가 느린 회선(또는 개발자 도구 네트워크 제한)에서 `/guide` → 학생 관리 > 등록하기를 펼침 → 캡처 자리마다 휴대폰 모양 스켈레톤이 깜빡이다가 캡처가 오면 서서히 나타나는지, 같은 절을 접었다 다시 펼치면(캐시된 이미지) 스켈레톤이 남지 않는지 확인

## 설계 요약
- **공유 버튼** (대화에서 확정): `GuideSection`·`GuideSubSection` 머리에 링크 아이콘 버튼. 머리 전체가 이미 펼침 버튼이라 그 안에 넣지 않고 형제로 나란히 둔다. 접힌 상태에서도 보이고 터치 영역 44px 이상. 버튼 이름(aria-label)은 `<제목> 링크 공유`
- **동작** (대화에서 확정): `navigator.share`가 있으면 공유 시트, 없으면 `navigator.clipboard.writeText` + 체크 아이콘·"링크 복사됨" 2초(시상 명단 복사와 같은 패턴). 공유 시트 취소(`AbortError`)는 조용히 무시. 복사 실패 시 짧은 실패 문구
- **공유 문구** (대화에서 확정): 세 줄. 링크를 마지막 줄에 둬야 카톡이 그 주소로 카드를 만든다
  ```
  고등부 출석부 사용 안내 — 학생 관리 · 지우기
  교사 비밀번호가 필요해요
  https://<배포 주소>/guide#members-delete
  ```
  작은 주제는 `절 제목 · 주제 제목`, 절은 절 제목만. 주소는 `location.origin + "/guide#" + id`
- **주소 갱신** (대화에서 확정): 페이지의 `goTo`에서 `history.replaceState`로 `#id`를 바꾼다. 같은 해시면 `hashchange`가 발생하지 않으므로 기존 앵커 처리와 충돌하지 않는다
- **카톡 미리보기** (대화에서 확정): 사용 안내 페이지는 클라이언트 컴포넌트라 metadata를 직접 내보낼 수 없다 → 서버 컴포넌트 `src/app/guide/layout.tsx`에 `title`·`description`·`openGraph`(제목 "고등부 출석부 사용 안내", 설명 "출석 체크부터 학생 관리까지 휴대폰 화면으로 안내해요", url `/guide`, 이미지는 기존 `og-img.png`)를 둔다. 미리보기에는 공개해도 되는 문구만
- **캡처 스켈레톤** (대화에서 확정): `GuideStep`의 캡처를 같은 비율(628×1326)의 상자로 감싸고, 상자에 기존 `Skeleton`과 같은 `animate-pulse bg-ink/8`을 깐다. 모서리는 휴대폰 틀에 맞춰 둥글게. 이미지는 처음에 투명하고 `onLoad` 후 페이드인하며, 다 받으면 깜빡임을 끈다. 동작 줄이기 설정이면 깜빡임·페이드 없음. `onLoad`를 쓰므로 `GuideStep`은 클라이언트 컴포넌트가 된다(부모 페이지가 이미 클라이언트라 부담 없음)
  - ⚠️ 캐시된 이미지는 하이드레이션 전에 다 받아져 `onLoad`를 놓칠 수 있다 → 스켈레톤이 영원히 남는다. `next/image`가 이 경우를 처리하는지 확인하고, 안 되면 ref로 `complete`를 확인한다
- 버린 안: 카카오 공유 SDK(앱 키·외부 스크립트 필요, 사용자 거절), 단계 단위 공유(어수선함), 전용 OG 이미지(글꼴 작업), 흐린 미리보기(42장 데이터 생성), 이미지 자체에 `animate-pulse`(다 받은 뒤에도 깜빡임)

## 영향 범위
- 화면: `/guide` 1개 — 인증 게이트는 그대로 **session**. 공유 버튼은 게이트 통과 후 렌더되는 본문 안에만 있다
- 코드: `src/components/guide/GuideSection.tsx`(버튼 배치), 공유 버튼 컴포넌트(새 파일, `src/components/guide/`), `src/app/guide/page.tsx`(`goTo` 주소 갱신, 절 제목 전달), `src/app/guide/layout.tsx`(새 파일, metadata), `src/components/guide/GuideStep.tsx`(캡처 스켈레톤, 클라이언트 컴포넌트로 전환)
- API·시트·환경변수: 변경 없음
- 테스트: `tests/e2e/`에 사용 안내 공유 spec 추가
- 문서: `CLAUDE.md`(폴더 구조·`/guide` 설명), `docs/migration-progress.md`, `docs/context-notes.md`
- 사용 안내 캡처(`public/guide/`): 파일은 그대로. 다만 절 머리 모양이 바뀌므로 재촬영 필요 여부를 PLAN에서 판단(스켈레톤과는 무관)

## 성공 기준
- [ ] 모든 절(7개)·작은 주제(7개) 머리에 공유 버튼이 있고 접힌 상태에서도 보인다
- [ ] 공유 버튼을 눌러도 절이 펼쳐지거나 접히지 않는다
- [ ] PC(공유 시트 없음)에서 누르면 클립보드에 세 줄 문구가 정확히 들어가고 "링크 복사됨"이 2초 뒤 사라진다
- [ ] `navigator.share`가 있는 환경에서는 공유 시트가 문구·링크와 함께 호출되고, 취소해도 오류가 보이지 않는다
- [ ] 칩·목차·대상별 카드로 이동하면 주소창 `#`가 그 id로 바뀌고 뒤로가기 기록은 늘지 않는다
- [ ] `/guide#members-delete`로 들어와 비밀번호를 통과하면 학생 관리 절과 지우기 주제가 펼쳐진다 (기존 동작 유지)
- [ ] `/guide` HTML에 사용 안내 `og:title`·`og:description`·`og:url`이 들어 있고, 다른 화면의 미리보기는 그대로다
- [ ] 캡처 응답을 늦추면 캡처 자리에 스켈레톤이 보이고, 응답이 오면 스켈레톤이 사라지고 캡처가 보인다
- [ ] 캐시된 캡처(절을 접었다 다시 펼침)에서 스켈레톤이 남지 않는다
- [ ] 캡처 로딩 전후로 단계 높이가 바뀌지 않는다(레이아웃 밀림 없음)
- [ ] 375px 화면에서 머리 제목과 공유·펼침 버튼이 가로로 넘치지 않는다
- [ ] `npm run test:e2e`, `npx tsc --noEmit`, `npm run build` 통과

## 후속 변경 1: 공유 문구 다듬기 (2026-11-14 추가)

- 상태: 초안 (사용자 승인 대기)

### 배경
배포 후 휴대폰에서 카톡으로 보내 미리보기 카드까지 확인했다(사용자). 다만 받은 메시지가 단조롭고, 첫 줄과 둘째 줄이 한 줄로 붙어 보였다.
```
고등부 출석부 사용 안내 - 말씀노트 체크하기 교사 비밀번호가 필요해요
[링크]
```
줄바꿈 하나가 공백으로 바뀌는 것으로 보인다(카톡 말풍선인지 공유 시트 미리보기인지는 미확인).

### 목표
- 받는 사람이 링크를 열기 전에 **무슨 내용인지** 알 수 있다 — 절 설명을 문구에 넣는다
- 이모지로 줄의 경계를 표시해, 줄바꿈이 사라져도 읽기 좋다
- 빈 줄로 문단을 나눠 링크가 문구와 분리되어 보인다

### 비목표
- 미리보기 카드(`og:*`) 변경 — 이미 확인됨, 그대로 둔다
- 작은 주제별 설명 문구 새로 쓰기 — 지금 작은 주제에는 설명이 없다
- 공유 시트·복사 동작 변경 — 문구만 바꾼다

### 설계 (사용자 선택: 아이디어 2)
절(설명 있음) — 예: 말씀노트
```
📖 [고등부 출석부 사용 안내]
✅ 말씀노트 체크하기
반 보관함의 QR을 찍고, 노트를 쓴 학생을 눌러요.

🔒 교사 비밀번호로 들어가요
👉 https://<배포 주소>/guide#notes
```
작은 주제(설명 없음) — 예: 학생 관리 · 지우기
```
📖 [고등부 출석부 사용 안내]
✅ 학생 관리 · 지우기

🔒 교사 비밀번호로 들어가요
👉 https://<배포 주소>/guide#members-delete
```
- 설명은 `GuideSection`의 `description`을 그대로 쓴다(새 문구를 만들지 않음)
- 공유 시트·클립보드가 같은 문구를 쓴다(기존 결정 유지). `share({ text })`만 넘기는 것도 유지
- 이모지는 📖·✅·🔒·👉 넷으로 제한
- 링크는 여전히 마지막 줄 — 카톡이 그 주소로 카드를 만든다(확인됨)

- 문서: `CLAUDE.md`(GuideShareButton 설명), `docs/context-notes.md`("공유는 text 하나로" 섹션의 세 줄 설명), `docs/migration-progress.md`
